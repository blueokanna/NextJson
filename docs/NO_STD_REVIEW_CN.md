# no_std 收敛与四种主格式优化

日期：2026-11-08。本文记录本轮工作区修改；上一轮见
[解码状态与基准复查](FOLLOWUP_REVIEW_CN.md)。原始性能数据、测量方法及局限见
[本轮基准报告](../benchmarks/results/nostd-2026-11-08/report.md)。

## 运行边界与迁移

`nextjson` 所有配置均为 `no_std + alloc`，不再提供 `std` 特性。默认仅开启
`derive`，另一个可选特性是 `simd`。没有新增第三方运行依赖。

这是接口变更，升级时需要处理以下内容：

- 删除依赖配置中的 `features = ["std"]`。流式读取改为实现 `nextjson::Read`，
  写入使用 `nextjson::Write` 和 `to_writer`；`to_io_writer` 已移除。
- 读取适配器返回 `nextjson::Result<usize>`。临时中断使用 `Error::interrupted()`；
  设备超时、重试期限由适配器控制。无限重试不是库可以代替设备驱动解决的问题。
- 移除标准库 `HashMap`、`HashSet`、路径类型及 I/O 错误转换实现。
  可用 `alloc::collections::BTreeMap/BTreeSet` 和显式字符串路径。
  网络地址类型使用 `core::net`；`Arc`、原子类型按目标能力编译。
- Envy 不再读取进程环境。调用方提供 `Envy.from_pairs(...)`，或通过 `decode`
  传入 UTF-8 的 `KEY=value` 行；重复键、空键和缺少等号的行报错。
- 六个示例改为 no_std 库目标，公开 `run() -> Result<String>`，通过返回值提供
  诊断文本。可构建并嵌入目标程序，不再作为依赖宿主打印的命令行程序。

derive 源码同样声明 no_std，但 Rust 的 `proc_macro` 编译器接口运行在宿主。
测试主体声明 no_std，Rust 自带测试运行器仍在宿主执行。计时、Serde 参考实现和
unwind 检查限定在 benchmark 项目中。裸机库编译证明目标依赖不含 std；不等于
已经在真实设备上验证了分配器、栈容量、中断环境和耗时上限。

## 核心改动

| 路径 | 改动 |
|---|---|
| JSON | 常见容器使用 16 帧内联栈；整数扫描避免逐位 128 位运算；基础数字数组批量编码；短整数、二进制精确分数直接格式化，其余浮点仍使用 core 格式化 |
| MessagePack | 已知长度容器直接写正确宽度的头，结束时核对实际数量；保留未知长度路径；基础数字数组批量编码，u64/f64 读取减少通用数值包装 |
| RON | 无转义字符串借用输入，数字不经临时 String；移除最终输出拷贝；补齐转义验证、分隔符检查和括号配对；区分 None、Some(None)、Some(())，char 使用字符字面量 |
| NDJSON | 直接将编码事件写成逐行 JSON，移除中间 Value 树及逐条重编码；换行扫描与行内完整性校验分离 |
| 共用解码 | Vec 使用分隔符返回的继续标志，避免每个元素重复判断容器结束；集合初始分配限制保持有效 |

批量编码只接受库已知的基础数值切片，不调用用户元素实现；容器上下文、深度、
非有限浮点策略仍受检查。自定义类型继续走正常事件路径。没有增加 unsafe，
SIMD intrinsic 仍限定在原有扫描模块。AVX2 改为编译目标显式启用，不依赖宿主
运行时探测；分发路径和标量参考结果都有测试。

固定 64 字节浮点缓冲以前无法写出某些极大值或次正规数，现在在普通十进制表示
放不下时改用科学计数法。回归覆盖有限极值、负零、快路径邻接位模式及一万组
确定性浮点位模式。Rust 1.78 的 core 不提供当前工具链中的所有浮点方法，相关
路径已按最低版本实现并实测。

RON 线格式有意修正：Some 值现在输出显式包装，unit 输出 `()`，char 输出单引号
字面量；解码仍接受旧版未包装的 Some 载荷。RON 仍是基于共同数据模型的子集，
结构体/枚举按 map/seq 编码，不承诺与 ron crate 的原生结构体、枚举语法完全互换。

## 已执行的验证

- Rust 1.99.1 默认配置和全特性：各 542 项测试通过；Rust 1.78 全特性同样通过。
- 关闭默认特性：64 项库测试通过。显式 AVX2：64 项库测试及严格 Clippy 通过。
- benchmark 项目：7 项测试通过，包括 RON 选项、字符与转义的双向参考解码，
  MessagePack 长度边界的参考字节对比，以及原有宿主 unwind 和报告解析检查。
- 严格 Clippy、rustdoc 警告检查以及两个 crate 的 docs.rs 配置构建通过。
- `x86_64-unknown-none` 和无原子指令的 `thumbv6m-none-eabi`：最小特性、
  全特性及全部库示例的 release 构建通过。CI 已加入这些门禁。

这些检查没有给出“零漏洞”的证明。输入配额、内存分配失败、递归栈预算和设备
超时仍需要按部署环境约束，具体见 [安全模型](SAFETY_CN.md)。性能数字只代表报告
中的数据和机器；目前也不能宣称四种格式在所有负载上都已接近或超过 Serde。
