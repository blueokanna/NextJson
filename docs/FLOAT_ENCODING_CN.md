# 浮点文本编码

JSON、NDJSON、RON 共用 `float` 模块；需要构造数值字符串的树形文本编码器也使用同一入口。
格式编码器管理容器、分隔符和写出错误，浮点模块处理数值、舍入与文本表示。

当前实现已移除上一版移植的转换核心、数字打包和幂表。整数区间计算、查表生成器和字节输出
在本仓库独立实现，没有引入外部运行时依赖。它仍使用 IEEE-754 舍入的数学基础，不宣称发明
全新的转换算法。次正规数及不能可靠判定的边界明确回退到 Rust core 的最短科学计数格式化。

## 转换依据

把正规数写成 `m × 2^e`，其中 `m` 包含隐含的有效位。根据二进制指数选取十进制倍率，
使缩放后的数值至少具有 17 位有效数字（f64）或 9 位（f32）。生成器用精确整数运算计算
`floor(2^(e + 68) × 10^k)`，并记录倍率是否精确。

运行时分别计算下中点、中心值和上中点的定点区间。二进制有效数为偶数时包含中点，奇数时
排除中点；二的整数幂单独处理下侧间距变小的情况。只有区间两端导出相同整数边界时才接受
结果，不能确定时回退。计算过程不依赖浮点乘除后的近似相等判断。

缩放后的 f64 舍入区间宽度小于 100，f32 小于 1000。因此，在对应的十进制网格上最多存在
一个候选。存在时直接生成其数字并删去尾零字节；不存在时检查更细的网格，按距离和末位
偶数规则选择候选。这省去了“整数除法删尾零，再把整数拆成数字”的重复工作。

全部 2300 个倍率由 [生成器](../benchmarks/generate_float_powers.py)生成。CI 检查源码与
公式完全一致，并核验 `u128` 乘积范围和上述区间宽度。推导与回退条件详见
[模块说明](../nextjson/src/float/README.md)。

## 写出路径

数字按四位一组查表，表项由十进制整数运算在编译期生成。数字、尾零处理和小数点插入共用
32 字节的已初始化栈缓冲，实际数字文本最长 24 字节。模块没有可变全局状态、锁、值缓存
或 `unsafe`。

较大的紧凑内存数组每 64 个数值分成一块，先转换，再按块预留容量并写出字节；临时空间
不随数组长度增长。有限性检查在该块写出前完成，预留容量不会进入有效输出长度。流式编码
保留原来的刷新阈值，漂亮格式和嵌套 NDJSON 保留各自的分隔规则。整数和精确八分之一倍数
继续直接写出，也覆盖整块量化数值，避免它们承担通用小数格式化的开销。

`f32` 使用自己的舍入区间，不先扩成 `f64`。例如 `1.2f32` 输出 `1.2`，不会输出
`1.2000000476837158`。负零保持为 `-0.0`，NaN 和正负无穷仍返回错误。

## 兼容性与验证

小数点位置在 -4 到 16 之间使用定点表示，其余使用科学计数法；定点整数保留 `.0`。
部分字节拼写与最初的 `Display` 路径不同，例如 `10000000000000000.0` 可变为 `1e16`。
数值逐位往返保持一致，依赖原始编码字节的签名或快照需要按此检查。

测试覆盖所有指数、二进制与十进制边界邻值、负零、非有限值、普通范围随机有效数、批次边界、
分段写出和并发调用。独立测试项目用 Serde 和 Ryu 作参考，仅用于验证，不进入库的构建依赖。

[实测报告](../benchmarks/results/float-independent-2026-11-08/report.md)保留全部采样、环境、
比较方法与剩余差距。正确性测试和当前机器的吞吐结果不等于对所有输入、硬件和部署环境的保证。
