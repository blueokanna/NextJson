# 生产加固记录：2026-11-08

后续修复和新增验证见 [解码状态与基准可信度复查](FOLLOWUP_REVIEW_CN.md)。

本轮依据可复现的失败用例修复实现，没有把通过测试等同于“零漏洞”或完整替代
Serde 生态。基础提交为 `1731daf2bd44e1ea8104d899369c69ee2ada937e`，结果针对本轮
修改后的工作区；保留了原有的 `0.1.5` 版本更新。

## 已修复

| 问题 | 修复后的行为 |
| --- | --- |
| 流式空白处理只检查现有缓冲 | 跨读取分块继续扫描，首尾空白与内存解析一致 |
| 分块边界处的对象尾逗号漏检 | 不同分块大小均拒绝非法尾逗号 |
| 忽略字段把 `}`、`]` 当成值消费 | JSON 与相关文本格式仍验证被忽略值的结构 |
| `Interrupted` 被直接视作失败 | 重试中断；其它 I/O 错误传播 |
| 预读后的保存位置位于 token 之后 | 保存 token 起点及所需容器状态，支持 untagged 重试 |
| BSON 回溯丢失字段类型 | 保存已经消费的类型标签 |
| 默认 JSON、CBOR 编码成功返回非法事件流 | 默认校验根值、键值顺序和容器闭合 |
| 深层编码缺乏递归保护 | JSON 编码器与公共校验包装限制 128 层容器 |
| `Map::retain` 的回调 panic 后索引失效 | 调用用户回调前失效索引，展开后仍可正确查询和修改 |
| `Map` 错误实现 `Eq` | 保留与 `Value` 一致的 `PartialEq`；NaN 不满足自反性 |

新增 `from_reader_with_limit` 与 `StreamDecoder::with_input_limit`。输入配额包含
空白；超过配额返回错误，回溯不能重置配额，untagged 重试不会掩盖入口的超限诊断。
达到边界后可能额外读取一个字节判断 EOF，该字节不保留。

`nextjson/tests/production_regressions.rs` 包含 16 项回归测试，其中多个测试遍历
每一种读取分块大小或边界值。最初加入的 7 项测试均在修复前失败，修复后通过。

## 兼容性与发布

- 正常且嵌套不超过 128 层的序列化事件流保持原有输出。非法自定义实现现在返回
  错误；超过深度上限的编码也返回错误。
- `FastEncoder` 仍可显式使用，但不再是顶层 JSON API 的默认策略。校验成本必须
  纳入性能评估，不能沿用旧版免校验基准作为默认入口的指标。
- 移除 `Map: Eq` 会影响显式要求这一 trait 的下游代码，调用方需使用 `PartialEq`
  或自行建立排除 NaN 的领域类型。
- 两个 crate 继承 `rust-version = "1.78"`；运行库与 derive 精确匹配 `0.1.5`。
  外部基准项目中的本地依赖版本和锁文件也已同步，没有升级第三方依赖。
- CI 增加默认特性测试，覆盖非 SIMD 的公开 API 路径。

## 验证范围

本机为 Windows 10 x86-64、Intel Core i7-11850H，稳定工具链为 Rust 1.99.1。
检查包括完整默认测试、完整全特性测试、Rust 1.78 测试、`no_std` 库测试、严格
Clippy、rustfmt、无警告 rustdoc，以及两份 crate 的离线打包验证。

最终默认配置、全特性配置和 Rust 1.78 配置各通过 513 项测试（含文档测试）；
`no_std` 库测试通过 63 项。Clippy 对全部目标、全特性及 `no_std + derive + simd`
配置启用 `-D warnings`。这些数量分别属于不同配置，不相加为独立用例数。

## 本机性能记录

原始数据见 [基准 CSV](../benchmarks/results/production-2026-11-08.csv)。运行命令：

```powershell
$env:NEXTJSON_BENCH_MS = '2000'
cargo bench -p nextjson --bench format_comparison --features simd --locked
```

每条路径先预热 200 次，再分别测量编码与解码各 2 秒。数据集为仓库既有的 128 条
记录；release 配置采用 thin LTO、一个 codegen unit，编译器为 Rust 1.99.1
（LLVM 23.1.1，`x86_64-pc-windows-msvc`）。运行期间未并发启动本轮构建或测试。

本次默认 JSON 行编码为 257.51 MB/s、解码为 126.63 MB/s，CBOR 为 599.82 MB/s
和 162.60 MB/s。MB 按十进制计算。显式 writer 行与原生向量入口的缓冲方式不同；
读取配额行测量的是流式解析，不应与内存借用路径混为一谈。

两次运行的数值波动明显，显式校验和免校验路径甚至出现吞吐顺序变化。这说明本机
采样不足以证明稳定的性能差异。本记录用于确认路径能够运行和保留原始观测，不给出
加速倍率、服务容量或回归阈值，也没有宣称相对修改前实现的性能提升。

外部 Serde 对照项目缺少本机 crates.io 缓存，离线构建未完成；未提供虚构的 Serde
对照数字。该项目的 manifest 元数据检查已通过。Linux、macOS、ARM、持续模糊
测试和部署负载测试不属于本轮本机验证结果。

输入配额不等于结果对象的内存上限，公共 API 也不能约束用户 trait 实现中的任意
循环、递归或分配。完整的部署边界见 [安全模型](SAFETY_CN.md)。
