# 生产加固复查：解码状态与基准可信度

日期：2026-11-08。基线为 `ce09939`，本文记录其后的工作区修改。
上一轮记录见 [生产检查](PRODUCTION_REVIEW_CN.md)，本文不覆盖其历史测量。

## 已修复的问题

| 问题 | 修复与验证 |
|---|---|
| `DecodeConfig::max_depth` 缺少文档，触发 `deny(missing_docs)` | 本机重现截图中的构建错误；补充字段含义和资源边界说明 |
| CSV 预读把 `001`、`1e3` 等字符串转成数值后再重建文本 | 预读不消费单元格，字符串读取直接使用原文；数值读取避免中间字符串克隆 |
| CSV、URL-form 的失败候选消耗输入，后续 untagged 候选无法恢复 | 保存并恢复表格模式、深度或字段源区间；覆盖多次字段和根值重试 |
| NDJSON 在换行前不检查当前 JSON 是否完整消费 | 标量入口及每条记录均检查行尾，拒绝 `1 2` 等尾随内容；回溯同时恢复当前行和行内位置 |
| CSV、URL-form 的大整数落入 `f64`，发生舍入 | 共用整数分类逻辑，支持 `i128`、`u128`；整数字面量越界直接报错 |
| 集合直接采用外部 codec 的长度提示 | 初始容量同时按元素数和元素大小限额；恶意 `usize::MAX` 提示不能触发巨额预分配 |
| 流式字符串逐字节检查缓冲区 | 批量扫描已缓冲的字符串片段，把 I/O 补充逻辑移出热路径；保持跨读取边界的 UTF-8 校验 |
| 极端偏移和诊断位置可能整数溢出 | 十六进制读取使用检查加法与切片访问，行列计数使用饱和加法 |

`nextjson/tests/extreme_regressions.rs` 新增 13 项回归测试。最初的 7 项在修复前均
失败，修复后通过；后续补充超大长度提示、128 位边界、嵌套回溯，以及 1、3、7、
4095、4096、4097、8192 字节读取分块下的大型 UTF-8 字符串。

CSV 现在拒绝未读完就关闭的行，URL-form 拒绝未消费字段值就继续读取键；依赖旧版
错误吞掉输入的自定义实现需要修正。整数溢出也不再转换成近似浮点结果。

## 基准链路修正

- 工作流先检查库能否编译，并执行报告解析器测试，再启动测速。
- stdout 原样保存为 CSV，移除会漏掉 `json-reader-limited` 等名称的筛选正则。
- 报告解析器拒绝列数错误、重复用例、非法数字、非有限值和缺失测量，不再填零。
- 删除没有实际编码过程的 `nextjson_bincode(na)` 占位测速；缺少实现时明确不测量。
- 异常输入检查汇总每次调用的结果，panic 不算成功拒绝，报告展示实际 panic 次数。
- 报告说明浮点自检容差、输入复制成本和测量边界，不从吞吐率推导安全性或精度结论。

已使用锁定依赖实际构建并运行外部对照程序。短时间窗冒烟运行产生 162 条生态吞吐
记录、9 条异常输入记录；原生矩阵产生 22 条路径记录。9 条异常输入在本次运行中
双方均拒绝，panic 计数均为零。这只描述这些样本。

原始数据及生成报告：

- [原生矩阵冒烟 CSV](../benchmarks/results/followup-2026-11-08/format_smoke.csv)
- [生态对照冒烟 CSV](../benchmarks/results/followup-2026-11-08/serde_smoke.csv)

## 修改前后实测

独立程序 `nextjson/benches/resource_paths.rs` 测量解码、分配和析构。基线从 `ce09939`
导出到独立目录，只补上阻止编译的字段文档并加入相同测试程序，未修改解码逻辑。
两侧均使用 Rust 1.99.1、release、thin LTO、单 codegen unit、`simd` 特性。
设备为 Windows 10 x86-64、Intel Core i7-11850H。

每次运行每条路径预热 20 次，采集 5 个各 200 ms 的样本。执行顺序为基线、修改版、
修改版、基线，测量期间未并发启动本轮编译或测试。合计每侧每路径 10 个样本。
[完整样本](../benchmarks/results/followup-2026-11-08/resource_paths.csv) 保留执行轮次。

下表为十进制 MB/s，括号内是最小值至最大值：

| 解码路径 | 基线中位数（范围） | 修改版中位数（范围） |
|---|---:|---:|
| 256 KiB ASCII 字符串流式读取 | 215.80（194.86–243.21） | 2910.73（1038.90–9501.57） |
| 同体积 Unicode 与转义字符串流式读取 | 171.33（154.53–188.80） | 463.50（315.68–493.99） |
| CSV：256 行 × 16 个整数 | 29.66（24.65–33.46） | 41.62（38.34–44.11） |
| NDJSON：256 行 × 16 个整数 | 124.86（113.73–131.40） | 126.73（114.96–133.31） |

流式字符串和 CSV 的样本区间有明显改善；ASCII 路径内部波动很大，不能据此承诺
固定加速倍率。NDJSON 两侧区间重叠，本轮没有充分证据宣称它加速。读取源为内存
切片，不包含磁盘或网络等待，也没有测量并发吞吐和尾延迟。

运行当前实现的命令：

```text
cargo bench -p nextjson --bench resource_paths --features simd --locked
```

## 检查结果与边界

- 默认配置、全特性配置、Rust 1.78 全特性配置各通过 526 项测试，含文档测试。
- `no_std` 与 `no_std + derive` 库测试各通过 63 项。
- 报告解析器 4 项测试通过；工作流编译测试会持续执行它们。
- 全目标全特性及三种 `no_std` 配置的 Clippy 均使用 `-D warnings` 并通过。
- rustfmt、无警告 rustdoc、两个 crate 的 docs.rs 构建配置均通过。
- 外部对照依赖保持独立锁文件；主工作区仍只有本地两个 crate，没有新增第三方依赖。

这些结果来自本机，不代表 GitHub 的 Linux/macOS 任务已经执行。未完成持续模糊
测试、独立安全审计、ARM 验证或实际服务的长时间负载测试。输入配额和初始容量限制
也不等于总内存或 CPU 时间限制；具体边界见 [安全模型](SAFETY_CN.md)。本轮修复
不能构成“所有代码零漏洞”或“任意极端负载均稳定”的证明。
