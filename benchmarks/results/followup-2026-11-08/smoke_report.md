## 4. 方法与边界

- release 构建，先预热，再按 NEXTJSON_BENCH_MS 分别测量编码与解码。原生矩阵固定预热 200 次；生态对照使用时间有界预热。
- MB/s = 每秒操作数 × 编码字节数 / 1e6；ns/op = 1e9 / 每秒操作数。不同格式的编码体积不同，不能仅凭 MB/s 排名。
- simd-json 的解码循环包含输入缓冲复制，其时间计入解码结果。
- numbers 用例的 serde_json 与 Serde NDJSON 往返自检允许最多 1 ULP 浮点误差，NextJson 与 simd-json 使用相等检查；这些自检条件不同，不能据此宣称双方具有相同的数值保真度。实际误差诊断写入运行日志。
- json 是默认校验路径；json-checked-explicit 与 json-trusted-explicit 使用相同 writer 缓冲方式比较策略；json-reader-limited 测量受输入配额约束的流式读取。
- 预读、校验和表示能力均属于测量条件。缺少对照行表示本次没有相应测量，不把缺失值写成零，也不自动归因于第三方库缺陷。
- 本报告只陈述输入 CSV 中的观测，不从吞吐数据推断浮点精度或安全结论。
- 共享运行器的负载、频率和温度会影响结果；单次比值不是性能保证，需用目标硬件和实际负载复测。
