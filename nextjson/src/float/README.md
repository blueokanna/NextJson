# Decimal conversion

This module is an independent implementation of directed integer intervals and
byte formatting. It contains no vendored Ryu, Zmij, or Dragonbox source or tables.
It uses ordinary IEEE-754 rounding mathematics; this is not a claim to have
invented a new floating-point conversion algorithm. Subnormal values and
ambiguous fixed-point boundaries use Rust core's shortest scientific formatter.
That fallback is explicit and allocation-free.

## Integer model

For a positive normal value, let `x = m * 2^e`, with the implicit significand bit
included in `m`. Choose `k` so that the scaled value has at least 17 decimal digits
for binary64, or 9 for binary32. The generated table stores

```
F = floor(2^(e + 68) * 10^k)
```

and whether this expression is exact. A boundary numerator `b` represents
`b * 2^(e - 2)`. Its scaled value is exactly `b * F / 2^70` when the table entry
is exact. Otherwise it lies strictly between `b * F / 2^70` and
`b * (F + 1) / 2^70`. All products fit `u128` by a checked generator invariant.

The upper midpoint has numerator `4*m + 2`. The lower midpoint has numerator
`4*m - 2`, except at a normal power of two above the smallest normal, where it
is `4*m - 1`. Even significands include midpoint endpoints; odd significands
exclude them. The implementation accepts a rounded boundary only when both
fixed-point bounds imply the same integer result. Uncertainty triggers the
fallback rather than an approximate answer.

## Shortest candidate

The scaled rounding interval is narrower than 100 integers for binary64 and
1000 for binary32. The generator checks both inequalities for every exponent.
At that spacing, there is at most one candidate. If present, its trailing zero
bytes can be removed directly; no repeated integer division is needed. Otherwise
we try the remaining finer decimal grids and select the closest valid candidate,
with ties rounded to an even final decimal digit. An uncertain nearest-candidate
test also falls back to core.

`generate_float_powers.py` constructs all 2300 entries from exact integer powers
and division. It does not read any reference implementation. CI regenerates the
expected source in memory and compares it with `powers.rs`.

## Formatting and integration

Four-digit groups come from a compile-time table generated by ordinary base-ten
arithmetic. Digit bytes share one 32-byte initialized scratch buffer. Leading
and trailing zero byte counts determine the active range; inserting a decimal
point uses bounded byte-group shifts. The longest wire number is 24 bytes.

Fixed notation is used for decimal point positions -4 through 16. Integral fixed
notation retains `.0`; other magnitudes use scientific notation. Negative zero
is retained and non-finite values are rejected before conversion. Binary32 uses
its own rounding interval, without promotion to binary64.

JSON, NDJSON and RON share this converter. Large compact in-memory float arrays
write bounded chunks and reject non-finite values before emitting them; streaming and pretty encoders
retain their existing flushing and framing paths. There is no mutable global
state, lock, per-value cache, unsafe code, or external Cargo dependency in this
module. Reference formatters exist only in the separate benchmark/test crate.

Tests cover every exponent, adjacent decimal grid values, both signs, normal and
subnormal boundaries, ordinary-magnitude random significands, and independent
reference comparisons. See [the Chinese design note](../../../docs/FLOAT_ENCODING_CN.md)
and the benchmark report linked there for measurements and remaining limits.
